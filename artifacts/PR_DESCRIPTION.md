# ЛР2: архитектура, тесты и observability

Сервис ЛР1 разделён на домен, usecase, HTTP-транспорт, репозитории и
инфраструктуру. Публичный контракт и SQL-миграции сохранены. Выполнена только
обязательная часть ЛР2; мутационное тестирование не добавлялось.

## Архитектура и решения

```text
cmd/trip-service → container
                     ├─ http/trip/{create,get,finish} → usecase/trip/{create,get,finish} → domain/trip
                     ├─ repository/{trip,idempotency} → domain/model
                     └─ infra/{postgres,telemetry}
```

- Точка сборки — `container`, который вызывается из `main` согласно подробному §4.1 задания. DI ручной, интерфейсы неэкспортируемые, объявлены у потребителей в `contract.go`.
- Переход `Finish` и валидация находятся в домене. Конкурентное завершение защищено условным SQL UPDATE.
- Доменные ошибки преобразуются в `Problem` только в `http/domainerror`; текст SQL, драйвера и стектрейсы не возвращаются клиенту.
- Транзакция передаётся через контекст. Создание/завершение и история атомарны; rollback работает при ошибке, отмене и панике.
- Сохранены существующие идемпотентность, очистка ключей, имя бинаря и generated-пакет ЛР1. Новых ручек и миграций нет.
- Счётчики обновляются после commit. Gauge активных поездок включён по обязательному `observability.md`.
- Middleware: Recover → Tracing → Logging → Metrics. Ответ буферизуется для безопасного восстановления даже после частичной записи.
- SDK providers передаются явно. Пул инструментирован `otelpgx`, адаптер переводит DB-метрику в секунды и добавляет актуальные DB-атрибуты.
- OTLP HTTP использует стандартные пути сигналов, поддерживает префикс базового URL. Есть также OTLP gRPC и W3C TraceContext.
- Shutdown останавливает HTTP и worker, затем сбрасывает метрики/трейсы при открытой БД и закрывает пул. Финальный gauge не обращается к закрытой БД.
- Конфиг линтера взят из курса, добавлены недостающие правила слоёв. Обязательные линтеры сохранены; настройка gofumpt переведена с deprecated `extra-rules` на её актуальные эквиваленты.

## Проверка

- `make lint`: 0 issues.
- `make test TEST_COUNT=2`: зелёный, `-race`; domain + usecase — 93,8%.
- `make test-integration`: зелёный, `-race -tags=integration -count=2`; PostgreSQL через testcontainers, отдельная схема на тест, реальные ошибки CHECK и полный rollback обеих таблиц.
- Интеграционные проверки OTLP protobuf по HTTP, включая базовый URL с префиксом, и завершения всего приложения.
- Повторная генерация OpenAPI и gomock не меняет файлы. Контракты/миграции не изменены, домен не импортирует инфраструктуру.
- Живые HTTP-проверки: 201/200/400/404/409; ошибка БД → чистый 500; при остановленном коллекторе сервис отвечает 200.
- Реальная проверка OTLP gRPC и W3C traceparent: родительский span сохранён; SIGTERM останавливает приложение с exit code 0.
- Реальный трейс найден по trace_id из JSON-лога; видны SQL-спаны и атрибуты таблиц. Метрики видны в Grafana.

Подробные результаты и артефакты: `artifacts/VERIFICATION.md`, `artifacts/verification/`.
